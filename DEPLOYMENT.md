# The Candle Tales — Production Deployment Documentation

This document describes the environment variable configurations and the recommended order of steps required to successfully deploy the application to production platforms such as Vercel, Railway, Render, etc.

> [!WARNING]
> Do NOT hardcode production credential secrets directly in code, properties files, or build scripts. All environment variable values must be configured securely directly inside your hosting provider's dashboard and must never be committed to Git.

---

## 1. Environment Configurations

### Frontend Environment (Vercel / Netlify / CDN)
Set this variable in your frontend hosting dashboard:

```env
# Full URL to your deployed Spring Boot production API (e.g. https://backend-production-api.railway.app)
# If frontend and backend are served through the same domain/reverse proxy, this can be left empty.
VITE_API_BASE_URL=
```

### Backend Environment (Railway / Render / VPS)
Set these variables in your backend hosting service dashboard:

```env
# Database Credentials
SPRING_DATASOURCE_URL=
SPRING_DATASOURCE_USERNAME=
SPRING_DATASOURCE_PASSWORD=

# Cloudinary Integration
CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=

# Security & CORS
JWT_SECRET=
FRONTEND_URL=

# Active Spring Profile (forces application-prod.properties configurations)
SPRING_PROFILES_ACTIVE=prod

# Optional password for initial database seeding of the Admin account
ADMIN_DEFAULT_PASSWORD=
```

---

## 2. Deployment Steps Order

Follow these steps in sequence for a correct launch:

1. **Create production MySQL database**: Provision a managed MySQL database instance (e.g. on Railway, AWS RDS, or Aiven) and retrieve the connection URL, username, and password.
2. **Configure backend environment variables**: Set all required database, Cloudinary, JWT, and active profile configurations in the backend hosting dashboard.
3. **Deploy backend**: Deploy the Spring Boot application (by pointing Render/Railway to the `/backend` folder).
4. **Obtain backend production URL**: Copy the public URL generated by your backend host (e.g. `https://thecandletales-api.up.railway.app`).
5. **Set `VITE_API_BASE_URL`**: Enter this backend production URL into the environment configuration of your frontend hosting dashboard.
6. **Build and deploy frontend**: Trigger the build and deployment of the frontend (pointed to `/frontend`).
7. **Set `FRONTEND_URL` to frontend domain**: Retrieve the public URL of the deployed frontend (e.g. `https://thecandletales.vercel.app`) and configure it as the `FRONTEND_URL` env variable in the backend dashboard so CORS security passes requests successfully.
8. **Test admin login**: Navigate to `/login` and sign in using the seeded admin account (`admin@thecandletales.com`) to confirm database access, JWT generation, and CORS.
9. **Test Cloudinary upload**: Create a test category or product containing an image file to verify Cloudinary integration works.
10. **Test WhatsApp ordering**: Add items to the cart, fill in the checkout form, click **Place Order via WhatsApp**, and verify the message text constructs correctly and opens WhatsApp.
11. **Test mobile UI**: Verify navigation, cart management, and layout responsiveness across mobile device viewports.
